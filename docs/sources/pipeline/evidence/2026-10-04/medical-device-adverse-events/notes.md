# medical-device-adverse-events (screen, 2026-10-04)

Scripts: `screen.py` (openFDA, MHRA, MDALL join, parked probes), `screen_hc.py` (Health Canada incident extract). Outputs: `results.json`, `results_hc.json`. All requests used the scout User-Agent, no keys, about 2 requests per second.

Process deviation, disclosed: the Health Canada MDALL `deviceidentifier` endpoint cannot be paged; the bare call returned the whole list (422 MB, 3,152,063 rows) once, over the 50 MB guidance. Nothing was retried, the file was used only for the join below and deleted afterwards. `licence/` (21 MB, 35,844 rows) was also fetched whole. Any replay must expect these sizes.

Verdict: dataset PASSES screening (3 non-RED new members plus 2 existing members, independent publishers, measured candidate links with hand checks above zero). Three members screened as usable, three PARKED.

## fda-maude-device-adverse-events (GREEN)
- `https://api.fda.gov/device/event.json` HTTP 200, no key. Total 26,136,889 reports; 2,503,728 with date_received in 2026; 73,153 in January 2015. Newest date_received 20260831; API `last_updated` 2026-09-22, so roughly one month behind.
- Sample: 300 reports received 2026-08-01 to 2026-10-04 (3 pages of 100). 124/300 (41%) carry `mdr_text` narrative entries (text types: "Description of Event or Problem", "Additional Manufacturer Narrative"). The rest have an empty narrative array. Event types in sample: Malfunction 272, Injury 24, Death 3, Other 1.
- Identifier fields: report_number, mdr_report_key, device.device_report_product_code (300/300), device.udi_di (101/300), device.model_number, catalog_number, lot_number, device.openfda (device_name, regulation_number, device_class), manufacturer_d_name. 510(k) K-numbers sit in `pma_pmn_number` (261/300 non-empty; 32 distinct K-numbers); `baseline_510_k__number` was empty in all 300. Patient block has age, sex, weight, problems and outcomes (personal-data review needed before publishing the patient block).
- Terms (https://open.fda.gov/terms/, fetched): "Unless otherwise noted, the content, data, documentation, code, and related materials on openFDA is public domain and made available with a Creative Commons CC0 1.0 Universal dedication." GREEN.
- Same-publisher links (FDA to FDA, not independent): 32/32 K-numbers cited in the sample exist in openFDA 510(k) (declared); 29/30 product codes exist in openFDA classification. FDA device recalls: 59,344 records, last_updated 2026-10-01.
- Scores 5/5/4/5/3/4/2 (the free API caps deep paging, so bulk files are needed; value is in narrative extraction and cross-regulator linkage).

## hc-medical-device-incidents (AMBER)
- Found via the "Medical device incidents database" link on https://www.canada.ca/en/health-canada/services/drugs-health-products/medeffect-canada/adverse-reaction-reporting/medical-device-problems.html (HTTP 200) which points to https://hpr-rps.hres.ca/mdi_landing.php?lang=en; the landing page offers "Download Full Extract". The path is built in the page script (`/files/extract.zip`), HTTP 200, 21,001,542 bytes, Last-Modified 2026-10-01 (folder inside is named "2026-07-31 extract").
- Contents (pipe-delimited): INCIDENT.dsv 327,430 incidents, receipt dates 1998-07-15 to 2026-07-29, 6,505 in 2026; INCIDENT_DEVICE 350,299 rows; INCIDENT_COMPANY 680,800 rows; INCIDENT_PATIENT_DEVICE_CODE 2.27 million rows; code tables. Types: mandatory problem report 295,300; voluntary 11,577; mandatory linked to recall 10,851; compiled foreign (US) 7,404. Source region: Canada 319,770, USA 4,476.
- Identifiers: INCIDENT_ID, DEVICE_ID (Health Canada device ID), TRADE_NAME, PREF_NAME_CODE (e.g. `73CAD`: all 350,299 are 2 digits plus 3 letters, the letters harmonised with the FDA product code), COMPANY_ID. Free-text columns: none (the script searched for narrative, text, description, comment, summary columns; only coded descriptions exist). So this member is a structured, coded feed with no narrative.
- Join to Health Canada's own MDALL register: 17,801/22,977 distinct incident DEVICE_IDs exist in the MDALL deviceidentifier list (same publisher, not counted as independent).
- Terms (Terms of use.pdf inside extract.zip; read with pdftotext): "This information is provided with the understanding that the data will be appropriately referenced and used in conjunction with this Terms of Use statement." The same text says counts are "not suitable for inferring the incidence or prevalence of a problem or for estimating risk". Disclaimer page https://hpr-rps.hres.ca/static/content/mdidisclaim.php: "Information related to the identity of people who report a voluntary incident is protected under the Privacy Act." No express open licence or commercial-reuse statement was found for the extract. AMBER with conditions (reference source, carry terms, no risk claims, ADR-0018 rights record before publication). Not RED: free public download, no login, no prohibition.
- Not in the open.canada.ca CKAN search for medical device incidents (229 hits, only reports, forms, shortage pages); the extract is only on the HPR site.
- Scores 4/3/4/3/3/4/3.

## mhra-device-field-safety-notices (AMBER)
- GOV.UK search API `https://www.gov.uk/api/search.json?filter_document_type=medical_safety_alert&filter_alert_type=field-safety-notices` HTTP 200: 618 weekly FSN list pages, newest 2026-09-29 ("Field Safety Notices: 21 to 25 September 2026"), 100 returned from 2024-12-10. Content API gives HTML body. 12 newest pages parsed: 122 entries, 117 with an MHRA reference (e.g. 2026/009/018/601/058), 49 with a model string. An entry has title ("Manufacturer: device"), a date, sometimes a device type, model list and an MHRA reference linking to the FSN document on `mhra-gov.filecamp.com` (HTTP 200, third-party host). The FSN PDFs were not fetched, so free-text depth is not measured; entry text on GOV.UK is a short listing.
- Terms: https://www.gov.uk/help/terms-conditions (fetched): "Most content on GOV.UK is subject to Crown copyright protection and is published under the Open Government Licence (OGL), which also sets out which content is exempt." OGL v3 (https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/, fetched): "You are free to: copy, publish, distribute and transmit the Information; adapt the Information; exploit the Information commercially and non-commercially for example, by combining it with other Information, or by including it in your own product or application." AMBER: attribution, third-party rights (FSN documents are manufacturer files on filecamp), "for information only" wording.
- Scores 3/4/3/3/5/3/4.

## Linkage (all measured on live data)
- MHRA FSN to MAUDE (candidate, manufacturer plus model token): of 36 FSN entries with a usable first model token, 20 had at least one MAUDE report with exactly that `model_number`. Hand check of the 20 (manufacturer name or corporate family aligned): 19 correct (Inspire 3024, Intervascular Intergard, Medtronic InterStim 978A1, Abbott Amplatzer Amulet, Abiomed controller, Hologic Aptima buffer, Philips BV Endura / Azurion / EPIQ / Allura / PIC iX, Olympus Evis Exera III colonovideoscope, Corin TaperFit and others); 1 wrong (NDI passive spheres matched a Medtronic Navigation report: different manufacturer name, unverified). Reviewed 19/20; matches are candidates for review, not automatic links.
- MAUDE UDI-DI to MDALL (declared on GTIN): 0/101 in the first sample and 0/500 in a larger sample of recent reports with UDI-DI. MDALL's `device_identifier` is a catalogue or label number: 261,520 of 1,550,527 normalised identifiers look like GTINs. Honest result: the declared UDI link gives zero here.
- MAUDE catalogue number to MDALL device identifier (candidate): 62/196 reports with a 6+ character catalogue number matched; the 17 distinct matches in the three sampled pages were hand-checked, 15 same product (Omnipod 5, Dexcom G7, MiniMed 780G, STAAR ICL, OptiCross, Endo GIA, MIS implant and others), 2 uncertain (Alaris I.V. set catalogue to an infusion-pump system licence; Cook Swartz doppler probe to a "doppler blood monitoring system" licence). Reviewed 15/17.
- Health Canada incident trade name to MAUDE brand_name (candidate): 21/40 distinct recent trade names had an exact brand hit; hand check 14/21 correct (Novum IQ, Spectrum IQ, Evolut FX, Azur plug, Belotero, Retracta, Amia, Inspiris and others); 7 wrong or unverified ("UNKNOWN ..." placeholders, VALVE PACK, STOPCOCKS, AUTOSOFT 90 with blank MAUDE manufacturer, a partial cobalt-chrome head).
- Declared FDA-internal: MAUDE cited K-number to 510(k) 32/32, product code to classification 29/30. These do not satisfy independence but make the clearance linkage deterministic.
- Product code is shared by FDA and Health Canada (`PREF_NAME_CODE` suffix) but is a classification attribute, not a record identifier, so it is a filter, never a link.
